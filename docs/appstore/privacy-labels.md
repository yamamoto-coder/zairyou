# App プライバシー(App Store Connect「Appのプライバシー」の回答)

根拠はサーバー実装(`server/api/*.php`, `server/schema.sql`)と `privacy.html`。
**トラッキング(広告目的の追跡)は一切なし** → 最初の質問「トラッキングしますか」は **いいえ**。
「データを収集していますか」→ **はい**。以下を1つずつ追加する。

用途の選択肢: アプリの機能 / 分析 / デベロッパの広告またはマーケティング / 製品のパーソナライズ / その他
「ユーザーに紐付く」= はい(会社アカウント単位で保存しているため)。「トラッキングに使用」= すべて いいえ。

| Apple のデータ種別 | 具体的な内容(根拠) | 用途 | 紐付け | 追跡 |
| --- | --- | --- | --- | --- |
| 連絡先情報 → **名前** | 担当者名・社員名(`users.name`) | アプリの機能 | はい | いいえ |
| 連絡先情報 → **メールアドレス** | ログイン ID・確認コード送付・サポート連絡(`users.email`) | アプリの機能、デベロッパの広告またはマーケティング(導入後の案内) | はい | いいえ |
| 連絡先情報 → **電話番号** | 登録時に取得(`companies.phone`。営業・サポート連絡用) | アプリの機能、デベロッパの広告またはマーケティング | はい | いいえ |
| ユーザコンテンツ → **写真またはビデオ** | 取り込んだ請求書・見積書の写真(`documents`) | アプリの機能 | はい | いいえ |
| ユーザコンテンツ → **その他のユーザコンテンツ** | 読み取った明細・料金表・発注文・納品先住所・仕入先情報(`kv_data`)、PDF 原本 | アプリの機能 | はい | いいえ |
| ユーザコンテンツ → **カスタマーサポート** | 使い心地アンケートの回答(`feedback`) | アプリの機能、分析 | はい | いいえ |
| 検索履歴 → **検索履歴** | アプリ内の検索語の履歴(HISTORY_KEY) | アプリの機能 | はい | いいえ |
| ID → **ユーザ ID** | 社内のアカウント ID・会社 ID | アプリの機能 | はい | いいえ |
| 使用状況データ → **製品の操作** | 操作回数・最終利用日(`activity_log`)、AI 利用量(`api_usage`) | 分析 | はい | いいえ |
| 使用状況データ → **その他の使用状況データ** | 初回アクセスのリンク元・UTM(流入経路。`companies.source`) | 分析、デベロッパの広告またはマーケティング | はい | いいえ |
| その他のデータ → **その他のデータタイプ** | 接続元 IP アドレス(ログイン失敗・登録申込の乱発防止。1日で削除) | アプリの機能(不正防止) | いいえ | いいえ |

収集していないもの(「いいえ」でよい): 位置情報 / 連絡先(端末のアドレス帳) / 健康 / 財務情報(支払い情報) /
閲覧履歴 / 診断データ(クラッシュログ SDK なし) / 購入(アプリ内課金なし) / 機密情報 / 端末 ID / 広告データ。

補足:

- 「デベロッパの広告またはマーケティング」を付けているのは、登録時のメール・電話を
  導入後のご案内(営業・サポート)に使う運用のため。使わないと決めるなら外してよい。
- 資材の購入履歴は「購入」(Purchase History)ではなく、利用者が取り込んだ**ユーザコンテンツ**として申告している
  (アプリ内で買い物をするわけではないため)。
- Apple の Nutrition Label は**アプリの機能に必須で・ユーザーが自分で入力し・稀にしか収集しない**データを
  任意で省略できるが、ここでは省略せず全部書く方針(後から指摘されるより安全)。
